# 互联网暴露面梳理工作方法

> 目标：把一家公司"在互联网上到底暴露了哪些东西"系统地找全。
> 思路：**从公司名 → 主域名 → 子域名/端口 → IP 段 → 前端/接口/公众号 → 反查补漏**，一环扣一环。

---

## 0. 整体流程图

```
公司名称 / IP / 域名
        │
        ▼
① ICP 备案查询  ──►  主域名、官网
        │
        ▼
② 天眼查/企查查  ──►  经营信息、股东、分公司
        │
        ▼
③ 分公司关联域名
        │
        ▼
④ 子域名枚举 + 全端口探测
        │
        ▼
⑤ IP → C 段探测、端口探测
        │
        ▼
⑥ 有效资产确认（访问 / 前端JS / 指纹 / 备案比对）
        │
        ▼
⑦ API 接口暴露面整理
        │
        ▼
⑧ 公众号 / 移动端资产（换 UA 头查看）
        │
        ▼
⑨ 补充手段：谷歌语法、LOGO 图搜
        │
        ▼
⑩ 汇总成资产清单
```

---

## 1. 第一步：查 ICP 备案，拿到主域名官网

**目的**：从"公司名 / IP / 域名"任意一个入口，找到公司真正的官网主域名。

**做法**：
- 在 ICP 备案查询平台，用 **公司名称** 查询 → 得到该公司备案的所有域名。
- 用 **已知 IP** 反查备案 → 得到该 IP 上绑定的域名。
- 用 **已知域名** 反查备案 → 得到备案主体（公司）及其名下其他域名。

**产出**：
- 主域名（官网）
- 备案主体（公司全称）
- 同主体下的其他备案域名（往往就是"隐藏资产"）

> 小技巧：备案主体名称要记下来，后面查企业信息、子公司域名都要用它。

---

## 2. 第二步：天眼查 / 企查查，摸清公司结构

**目的**：一家公司的资产不只在自己名下，**子公司、分公司、参股公司** 往往也有独立域名和系统。

**重点看**：
- 工商基本信息（公司全称、曾用名）
- 经营信息（主营业务 → 推测会有哪些系统）
- 股东结构（母公司、关联公司）
- **分公司 / 子公司列表**（重点！）
- 对外投资

**产出**：
- 一份"关联公司清单"，每个公司都要回到第一步再查一次备案。

---

## 3. 第三步：分公司关联域名挖掘

**做法**：
- 对每个分公司 / 子公司名称，重复 **ICP 备案查询**。
- 用分公司名称做 **谷歌语法搜索**，找它自己的官网。
- 对比：分公司域名是否与总公司不同？不同就当成新的资产起点。

**产出**：
- 一张"公司 → 域名"的关联表。

---

## 4. 第四步：子域名枚举 + 全端口探测

**目的**：主域名只是冰山一角，真正的系统大多藏在子域名里。

**子域名枚举常用手段**：
- 字典爆破（常见子域名列表）
- 证书透明度日志（CT 日志）
- 搜索引擎 / 第三方子域名字典库
- DNS 数据集、被动 DNS
- 页面里的外链、JS 里的域名引用

**端口探测**：
- 对每个解析出的有效域名 / IP 做 **全端口扫描**（1-65535）。
- 常见重点端口：`80 / 443 / 8080 / 8443 / 22 / 3389 / 3306 / 6379 / 9200` 等。

**产出**：
- 子域名清单 + 开放端口清单。

---

## 5. 第五步：IP 与 C 段探测

**目的**：同一个公司常把资产放在相邻 IP 上，扫 C 段能发现"没挂域名"的裸系统。

**做法**：
- 拿到任一有效 IP 后，查它的 **C 段（/24）** 和归属信息（ASN、Whois）。
- 对 C 段做 **端口探测**。
- 判断哪些 IP 属于同一主体（备案 / 归属 / 反查绑定域名）。

**产出**：
- IP 段资产清单，包含只开端口、没有域名的"隐藏系统"。

---

## 6. 第六步：确认"这个资产到底是不是它的"

拿到一堆域名 / IP 后，要判断 **关联性**，避免把别人的资产算进来。

**三种确认方法**：

| 方法 | 怎么用 | 说明 |
|------|--------|------|
| **直接访问** | 打开网站看内容、logo、版权信息 | 最直接 |
| **前端 JS 提取** | 抓页面 JS，提取里面的 URL / 域名 / 接口 | 常能发现关联系统和内网域名 |
| **指纹识别** | 看框架、CMS、favicon、标题、证书 | 同主体系统往往指纹一致 |
| **ICP 备案比对** | 看页面底部备案号是否同一主体 | 强关联证据 |

**前端 JS 重点看**：
- 硬编码的域名、子域名
- API 路径、接口地址
- 第三方服务（OSS、CDN、地图、支付）
- 注释里的测试地址、内网地址

---

## 7. 第七步：API 接口暴露面整理

**目的**：网站的每个功能背后都有接口，接口是暴露面的核心。

**怎么找**：
- 浏览页面时用 **浏览器开发者工具 → Network**，记录所有 XHR / Fetch 请求。
- 从前端 JS 里搜 `api`、`/v1/`、`/v2/`、`graphql`、`rest` 等关键词。
- 看 Swagger / OpenAPI 文档地址（如 `/swagger-ui.html`、`/api-docs`）。
- 整理接口清单：**URL、方法、参数、是否需要认证、返回什么数据**。

**产出**：
- 一张"功能 → 接口 → 域名"的映射表，方便后续判断哪些接口暴露过度。

---

## 8. 第八步：公众号 / 移动端资产

**目的**：很多公司有"只给手机看"的业务系统，PC 上找不到。

**做法**：
- 找到公司 **公众号 / 小程序 / 移动端 App** 对应的网站域名。
- 如果这个域名 **和官网不一样** → 把它当成新起点，**重新做子域名枚举 + C 段探测**。
- 公众号网站一般面向手机端，**在电脑上访问会显示不全或被拦截**。
  - 解决办法：**修改请求的 UA 头**，伪装成手机浏览器（如 iPhone Safari / 微信内置浏览器 UA），即可在电脑上正常查看。

> UA 头示例（微信内置浏览器）：
> `Mozilla/5.0 (iPhone; CPU iPhone OS 16_0 like Mac OS X) ... MicroMessenger/8.0.x`

---

## 9. 第九步：补充手段，查漏补缺

当前面都做完，还想找更多暴露面时，用这些方法补：

| 手段 | 说明 |
|------|------|
| **谷歌语法（Google Dork）** | `site:域名`、`"公司名" inurl:admin`、`intitle:"公司名"`、`filetype:pdf 公司名` 等，找官网、后台、文档 |
| **LOGO 图搜** | 用公司 LOGO 做以图搜图，能找到没被收录、没备案或换了域名的站点 |
| **证书透明度日志** | 查同一个证书下签发的所有域名 |
| **GitHub / 代码托管搜索** | 搜公司名、域名，可能找到泄露的配置和接口 |
| **招聘网站 / 招标公告** | 常暴露内部系统名称和技术栈 |

---

## 10. 第十步：汇总成资产清单

最后把所有信息整理成一张总表，方便后续跟踪和复测。

建议字段：

| 字段 | 说明 |
|------|------|
| 公司 / 主体 | 归属哪个公司 |
| 域名 / IP | 资产地址 |
| 端口 / 协议 | 开了什么服务 |
| 系统名称 | 前台是什么系统 |
| 指纹信息 | 框架、CMS、服务器 |
| 备案信息 | 备案号、主体 |
| 关联依据 | 怎么确认是它的（访问/JS/指纹/备案） |
| 接口清单 | 关键 API |
| 备注 | 测试账号、异常点等 |

---

## 快速检查清单（Checklist）

- [ ] 用公司名 / IP / 域名查过 ICP 备案
- [ ] 天眼查看过股东、分公司、子公司
- [ ] 每个分公司都单独查过备案和官网
- [ ] 主域名做过子域名枚举
- [ ] 所有有效域名做过全端口探测
- [ ] 有 IP 的做过 C 段探测
- [ ] 每个资产都做过关联性确认（访问 / JS / 指纹 / 备案）
- [ ] 前端 JS 提取过 URL 和接口
- [ ] API 接口整理成清单
- [ ] 公众号 / 小程序域名单独扫描过
- [ ] 移动端页面用手机 UA 查看过
- [ ] 用谷歌语法 / LOGO 图搜补过漏
- [ ] 汇总成资产清单表

---

## 注意事项

- 所有扫描和探测 **必须在获得授权的范围内** 进行，遵守法律法规和客户约定。
- 扫描频率要控制，避免影响目标业务正常运行。
- 发现的敏感信息（账号、密钥、接口）要妥善保管，只在授权范围内使用和报告。
